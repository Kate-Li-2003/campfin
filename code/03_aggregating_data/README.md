# 03_aggregating_data — building the masterfiles

## TL;DR

This directory builds the project's two **masterfiles**: big lookup tables that map a donor's employer (or an organization's own name) to an industry code. Everything downstream — race classification, the ML classifier — starts by checking these tables before doing anything cleverer.

- **Masterfile #1** (`data/03_input/masterfile/running_list.csv`) holds **real NAICS codes** gathered from static sources (OpenSecrets, H-1B filings, California EDD, a NAICS/OpenSecrets crosswalk, and manual review).
- **Masterfile #2** (`data/03_input/masterfile/running_list_custom.csv`) is a **derived editorial view** of Masterfile #1, translated into the newsroom's custom category scheme (Finance split from Insurance, Renewable Energy carved out of Utilities, unions split public/private, etc.).

**The most common maintenance task — changing the categories — does not require touching any code.** Edit `data/03_input/masterfile/custom_naics_labels.csv`, rerun `0306_build_custom_masterfile.py`, done.

## Run order

```
0301_build_running_list.py            seed Masterfile #1 from OpenSecrets + H-1B
0302_classify_donors.py               add EDD lookups for specific donor files
0303_extend_running_list_from_edd.py  bulk-extend Masterfile #1 via EDD
0304_map_opensecrets_naics_crosswalk.py  fill NAICS codes for OpenSecrets-only rows
0305_extend_running_list_from_manual.py  fold in manually reviewed labels
0306_build_custom_masterfile.py       derive Masterfile #2 (custom scheme)   <- NEW
```

Steps 0301–0305 are slow/occasional (they hit APIs or ingest new review sheets). Step 0306 is fast and rerun whenever the editorial taxonomy changes.

## What each file does

| File | Kind | Purpose |
|---|---|---|
| `0301_build_running_list.py` | procedural | Seeds Masterfile #1 from `opensecrets_matches.csv` + `H1BEmployer_match.csv`. |
| `0302_classify_donors.py` | procedural | EDD (CA employment agency) name lookups for a donor file; real NAICS codes, often 6-digit. |
| `0303_extend_running_list_from_edd.py` | procedural | Same EDD lookup, applied in bulk to extend Masterfile #1. Caches in `.edd_naics_cache.json`. |
| `0304_map_opensecrets_naics_crosswalk.py` | procedural | Maps OpenSecrets industry categories to NAICS via `NAICS_OpenSecrets_Crosswalk_Mapped.xlsx`, filling rows with no NAICS. |
| `0305_extend_running_list_from_manual.py` | procedural | Ingests manual review sheets (`data/03_input/training data (manual classifications)/`). **Changed:** rows with real NAICS go into Masterfile #1; rows carrying custom codes (88, 77a, …) are diverted to `manual_custom_overrides.csv` for 0306. |
| `0306_build_custom_masterfile.py` | procedural (new) | Runs every Masterfile #1 row through the sub-code resolver and writes Masterfile #2. Applies `manual_custom_overrides.csv` last (manual beats automation). |
| `subcode_resolution.py` | procedural (new) | The shared **sub-code resolver** — the only place that maps parent NAICS codes into the custom scheme. Also used by stage 07. See "How resolution works" below. |
| `edd_naics_lookup.py` | procedural | EDD API client used by 0302/0303. |
| `03_OpenCorporates_naics_lookup.py`, `03_webscraping_addtl_data.py` | procedural | Supplementary lookups/scrapes; write to `output/03_output/`. |

## How resolution works (0306 / subcode_resolution.py)

For each entity (name, occupation, parent NAICS code), in order:

1. **Employer-name regex pass** — the regex rules in `custom_naics_labels.csv`, applied in file order, later rows overwriting earlier ones. This is why political categories (88 PACs, 90 Candidates, 91 Parties) sit at the bottom of the file: they always win.
2. **Occupation regex pass** — rules marked `applies_to = occupation` (currently 100 Retired/Homemaker/Student). Runs second so occupation wins for individuals.
3. **Partition fallback** — if the parent code is a *partitioned* sector (52, 56, 77 — codes that no longer exist as terminal labels) and no regex fired, an embedding model compares the entity text against each sub-code's plain-language `description` and picks the nearest. Confidence is recorded.
4. **Passthrough** — any other parent code is already a valid label in the custom scheme and is kept as-is.

Every Masterfile #2 row records `custom_code`, `custom_label`, `resolution_method` (regex / occupation-rule / embedding / parent-passthrough / manual / unresolved) and `resolution_confidence`. Rows with method `embedding` and low confidence are the ones worth human review.

## Changing the categories (the editorial workflow)

1. Edit `data/03_input/masterfile/custom_naics_labels.csv`. Columns:
   - `naics_code`, `naics_label` — the terminal code and display label.
   - `parent_code`, `kind` — `sector` (standard NAICS), `carveout` (subset of a sector that still exists, e.g. 22a from 22), `partition_child` (sector fully replaced by its children, e.g. 52a/52b replace 52), `custom` (76–91), `fallback` (99).
   - `applies_to` — whether the regex matches the employer name or the occupation.
   - `name_regex` — keyword rule; **row order = precedence (later wins)**.
   - `description` — plain-language text used by the embedding fallback for partitioned sectors.
2. Rerun `python code/03_aggregating_data/0306_build_custom_masterfile.py`.
3. Rerun stage 07's `0705_classify_race_custom.py` for any races you want restated.

Nothing else needs to change — the resolver and classifiers read the schema from this file at runtime.
