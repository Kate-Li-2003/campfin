# Change review — custom codes, keyword priors, and train/serve fixes (2026-07-06)

Motivated by the reviewed benchmark ("Governor contribution classifications"
export; ground truth = `naics_final_classification`): the ML classifier scored
**47.3% top-1** at the entity level (245 entities), systematically
over-predicting 54/81, missing every political entity (88/90/91), ignoring
strong industry tokens ("Farms", "Energy", "Media"), and ignoring occupations
("Farmer", "Quantitative Trader") because it was trained on bare company names
only.

## Result

Measured by `0704_benchmark_reviewed.py` (same 245 entities, NAICS scored at
the normalized 2-digit sector level):

| metric                    | before | after |
|---------------------------|--------|-------|
| top-1, entity level       | 0.473  | 0.661 |
| top-1, donation level     | 0.452  | 0.652 |
| errors fixed / broken     |   —    | 50 / 4 |

By layer (entity level): custom rules n=24 acc=0.92, keyword priors n=36
acc=0.78, ML n=185 acc=0.61. Largest per-code gains: 90 (0.00→0.93),
92 (0.00→1.00), 11 (0.29→0.79), 51 (0.17→0.67), 79 (0.00→0.50).

## New files

- **`CUSTOM_CODES.md`** — the custom code mapping (76 Associations, 77 Unions,
  78 Defense, 79 Tech/software/AI, 88 PACs, 90 Candidate committees,
  91 Parties, 99 Unknown), precedence rules, and where each layer is enforced.
- **`text_features.py`** — shared embed-text builder (format "v2"):
  junk-employer detection ("Self Employed-Phil Mickelson", employer = donor's
  own name, "Refunded"), occupation-led text for individuals. Used by 0701 and
  0702 so training and serving text always match.
- **`keyword_priors.py`** — high-signal employer/occupation token → code
  priors (Farms→11, Oil→21, Energy→22, Media→51, AI/software→79, Dept of→92,
  quantitative trader→52, …). Overrides ML only when
  `ml_naics_code_conf < 0.55` (`--prior-threshold`); the fired prior is always
  recorded in a new `prior_naics_code` column. Ordering encodes "area of
  business beats business type" ("Healthcare Central LLC" → 62).
- **`0704_benchmark_reviewed.py`** — scores baseline (ML only) vs the full
  stack against the reviewed file using its precomputed ML columns (no
  encoder needed). Flags: `--entity-level`, `--per-code`, `--prior-threshold`.
- **`data/03_input/benchmarks/governor_contribution_classifications.xlsx`** —
  the reviewed benchmark, checked into the repo.
- **`data/03_input/training data (manual classifications)/occupation_naics_seed.csv`**
  — ~120 occupation → NAICS seed rows for training augmentation.

## Modified files

- **`data/03_input/masterfile/custom_naics_labels.csv`** — was a single
  PAC→88 regex; now ordered rules (later rows win) for 76, 77, 79, 78,
  92 (tribal), 88 (broadened: COPE, union legislative/candidate funds, IE
  committees), 91, 90 ("X for Assembly/Congress/… ", "Committee to Elect",
  "Friends of"). Note: these rules match the entity name, and for individual
  donors the entity IS the employer, so e.g. an employee of "VAL Property AI"
  is stamped 79.
- **`0702_predict_unmatched.py`** — after ML promotion it now runs, in order:
  (1) keyword priors on the previously-unmatched rows, (2) the custom-code
  regex overrides (re-applied so ML never final-stamps a political entity),
  (3) a 99 fallback for anything still uncoded (ml_* columns preserved).
  Embed text is built by `text_features` in the format recorded in the
  models dir (`text_format.txt`; legacy models keep the v1 format). New
  `data_source_1` values: `keyword prior`, `custom rule` (post-ML),
  `uncategorized fallback`. New CLI: `--prior-threshold` (default 0.55).
- **`0701_train_classifier.py`** — training augmentation (on by default,
  `--no-aug` reverts): occupation seeds rendered as "occupation: {occ}" plus
  labeled individuals harvested from 05 outputs, both in the exact v2 serving
  format. Writes `text_format.txt` so 0702 stays in sync. This fixes the
  train/serve mismatch behind the manufacturer-employee cluster (biggest
  remaining error mass, 54→31-33).
- **`0703_evaluate.py`** — NAICS accuracy now scored at the normalized
  2-digit sector level (manual "33" matches predicted "31-33";
  3+ digit codes truncated), via `normalize_naics_2digit`.

## Threshold choice

Prior-threshold sweep on the benchmark: 0.55 → 0.592, 0.65 → 0.596,
0.75 → 0.592, always-override → 0.596 (before the later rule fixes), with
regressions growing from 3 to 7 as the threshold rises. 0.55 kept as the
default: near-best accuracy, fewest correct-rows broken.

## Known regressions (4 benchmark rows)

"Effective Ventures US"→52 (truth 81), "Dynamic Energy Solutions"→22 (truth
23), "Siman Enterprises"+"Real Estate Professional"→53 (truth 54), "American
Medical Response"→62 (truth 54). All are genuinely ambiguous names; accepted.

## Remaining error classes (not fixable lexically)

Acronyms (CAPA21, GCEC), no-signal names (The Wonderful Company, SuperSet,
Socure, Cowboy Space) — need lookup/LLM enrichment. Weak-name manufacturer
employees (Lighthouse Worldwide Solutions et al.) — targeted by the retrain.
